## Что это за проект
Движок мультилендинга для юридической антикризисной службы (Москва и МО).
Партнёры: Рамис + Ильдар (автоматизация, продукт, инфра) × Иван Спирин (юридическая экспертиза).
Стартовый сегмент: горячий кризис бизнеса — арест счетов, налоговые проверки, ФСПП, субсидиарка.
Модель: один движок, посадочные генерируются из конфига `content/landings.ts`. Новая боль = новый объект в конфиге, не новый код.

## Стек
- Next.js 15 (App Router, TypeScript)
- Деплой: Coolify / Docker / VPS (output: 'standalone')
- Заявки: `/api/lead` шлёт их напрямую в Telegram (n8n из цепочки убран). Фронт ходит только в свой `/api/lead`
- Бот-секретарь: вебхук Telegram → `/api/telegram/webhook`; ИИ-ответ — необязательное звено, при любом сбое отдаётся шаблон
- Аналитика: Яндекс.Метрика

## Порты проекта
Порты проекта YurKom: **dev 3170, preview 3171**. Закреплены в `package.json` (`next dev -p 3170`, `next start -p 3171`) — запускать серверы без явного порта нельзя, Next иначе занимает 3000 и уезжает на соседний проект.

Не использовать порты других проектов: **Ecosystem — 3100, mock — 4000**. Порт `3000` в `Dockerfile` и в инструкции Coolify — внутренний порт контейнера, к хостовым не относится и менять его не нужно.

Перед запуском проверять занятость порта и **НЕ останавливать чужие процессы** — только свои, по PID с проверкой командной строки:
```powershell
$own = Get-NetTCPConnection -LocalPort 3171 -State Listen -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty OwningProcess -Unique
foreach ($id in $own) {
  if ($id -eq $PID) { continue }
  $cmd = (Get-CimInstance Win32_Process -Filter "ProcessId=$id").CommandLine
  if ($cmd -like '*YurKom*') { Stop-Process -Id $id -Force }
  else { "PID $id на этом порту не мой — не трогаю" }
}
```

## Процессы: headless-Chrome и фоновые серверы — НИКОГДА не убивать по имени
На машине параллельно работают другой проект (PMS) со своим headless-Chrome и обычный рабочий браузер пользователя. Массовый kill выкидывает пользователя из браузера и ломает соседний проект.

**Запуск headless-Chrome — всегда изолированный инстанс:**
```
--user-data-dir=C:\temp\chrome-debug-yurkom
--remote-debugging-port=9222
```

**Уборка — только свой инстанс, одним из способов:**
1. Предпочтительно — закрыть через CDP: `Browser.close` по своему `remote-debugging-port`.
2. По PID, который сам же и запустил (запомнить при старте).
3. Только для Chrome — по уникальному `user-data-dir`:
   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='chrome.exe'" |
     Where-Object { $_.CommandLine -like '*chrome-debug-yurkom*' } |
     ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
   ```

**Про фильтры по командной строке — отдельно.** Такой фильтр допустим ТОЛЬКО когда подстрока уникальна для своего процесса (`chrome-debug-yurkom` — уникальна). Для `node.exe` уникальной подстроки нет: `next*start` совпадает с `start-server.js`, который есть у любого Next-сервера, включая dev соседнего проекта. **Уже приводило к тому, что был убит dev-сервер `Work\Ecosystem`.** Фоновые node-процессы гасить ИСКЛЮЧИТЕЛЬНО по PID, сохранённому при запуске, или через механизм фоновых задач харнесса. Никаких `-like` по `node.exe`.

**Свой фоновый сервер гасить по владельцу порта** — это привязка к конкретному процессу, а не фильтр по имени. Обязательно с проверкой, что процесс действительно из этого проекта:
```powershell
$own = Get-NetTCPConnection -LocalPort 3150 -State Listen -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty OwningProcess -Unique
foreach ($id in $own) {
  $cmd = (Get-CimInstance Win32_Process -Filter "ProcessId=$id").CommandLine
  if ($cmd -like '*YurKom*') { Stop-Process -Id $id -Force }
  else { "PID $id на этом порту не мой — не трогаю" }
}
```

**Read-only переменные PowerShell — про них помнить отдельно.** `$pid` занят автоматической переменной с PID самой оболочки и присвоению не поддаётся: `$pid = 1317` падает с `VariableNotWritable`, а дальше по скрипту `Stop-Process -Id $pid` целится в собственный процесс. **Такое уже случалось.** Свои переменные называть `$ownPid`, `$serverPid`, `$targetId`. Тот же запрет на присвоение — `$host`, `$true`, `$false`, `$null`, `$input`, `$args`, `$error`. Перед `Stop-Process` печатать, что именно гасим, и убеждаться, что PID не равен `$PID`.

**ЗАПРЕЩЕНО безусловно:**
- `taskkill /IM chrome.exe`, `/IM node.exe` и любой другой kill по имени процесса
- kill по маске, по фильтру окон (`/FI "WINDOWTITLE eq *"`), `pkill -f chrome`, `Stop-Process -Name`
- то же самое для `node.exe`: dev-серверы и сборки соседних проектов убивать нельзя. Фоновый сервер гасить только по своему PID или через механизм фоновых задач харнесса.

**Если точечно убить не получается — не убивать вообще.** Оставить процесс висеть и сказать об этом пользователю: он закроет сам. Массовый kill запрещён, даже когда «мешает» и кажется безопасным.

- Тёмная база: глубокий графит `#0E0F12` (не плоский чёрный)

- Дизайн-инструменты: плагин ui-ux-pro-max, frontend-design, magic MCP — использовать по назначению

## Env-переменные (Coolify)
- `NEXT_PUBLIC_METRIKA_ID` — ID Яндекс.Метрики. Обязательно отметить как Available at Buildtime, иначе Метрика молча не включится.
- `NEXT_PUBLIC_SITE_URL` — для sitemap/robots/канонических. Тоже Buildtime.
- `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather. Server-side, не публичный. Утёкший токен = чужой доступ к переписке с клиентами.
- `TELEGRAM_CHAT_ID` — рабочая группа, куда падают заявки с формы и пересылки из бота. У группы значение отрицательное.
- `TELEGRAM_WEBHOOK_SECRET` — сверяется с заголовком `X-Telegram-Bot-Api-Secret-Token`. Не задан → вебхук принимает запросы без проверки, для прода так нельзя.
- `LEAD_FALLBACK_FILE` — куда писать заявки, не дошедшие до Telegram. Не задан → системный temp. В Docker указывать путь на томе, иначе лог умрёт вместе с контейнером.
- `ANTHROPIC_API_KEY` — ключ для ИИ-ответов бота-секретаря. Server-side, не публичный. Не задан → бот работает на шаблоне, ничего не падает.
Проект должен собираться и работать без заданных env (Метрика и Telegram просто отключаются, билд не падает).

## Приём заявок
`/api/lead` устроен так, что заявка не теряется ни при каких сбоях интеграции:
- honeypot заполнен → тихий `ok: true`, дальше заявка не идёт (бот не должен понять, что его отсеяли);
- rate limit по IP (5 запросов в минуту, in-memory) → `429`;
- валидация: `situation` обязательна, 10–5000 символов, телефон до 32 → `400` с текстом для формы;
- `source` — слаг посадочной либо `homepage`; неизвестное значение схлопывается в `unknown`, чтобы в чат не приезжало произвольное содержимое запроса;
- Telegram не настроен, ответил ошибкой или не уложился в 5 сек → клиент всё равно получает успех, а заявка пишется в fallback-лог с маркером `LEAD_FALLBACK` (stdout + файл).

**Ответ Telegram клиенту не возвращается.** Что там с доставкой — внутренняя кухня; посетителю показываем только «заявка принята».

## Юр-развязка
Домены, аккаунты Метрики, Директа, VPS — на почтах с доступом у команды, не «внутри» ООО брата-юриста. Бренд в текстах не привязывать жёстко к конкретному юрлицу, чтобы можно было сменить ООО без переделки.

Перед любой командой, требующей подтверждения, сначала одним предложением по-русски объясни: что команда делает и что изменится необратимо. Если ничего необратимого — так и скажи.
